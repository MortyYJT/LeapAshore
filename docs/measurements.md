- Notes: design in `openspec/changes/archive/2026-10-30-advisor-limits/`. Redis client `redis` (redis-py asyncio); local compose maps it to 127.0.0.1:56379, production does not expose it; `noeviction`, 256 MB. The subject is what `get_subject` returns (the account in sign-in mode, the anonymous cookie's id otherwise); **both subject and IP are checked** and either one full refuses. Sliding windows use sorted sets; one Lua script checks the three daily quotas and every window and records only when all pass (refused requests take no slot); time comes from Redis `TIME`. Defaults: subject 10/minute and 60/hour, IP 30/minute and 200/hour; daily tokens 200,000 per subject, 600,000 per IP, 2,000,000 for the site; "a day" is Beijing time. Daily quotas: the admission script reserves 8,000 tokens (`ADVISOR_TURN_TOKEN_RESERVE`) on the subject, IP and site counters; every model call adds its reported usage (LangChain callback); the turn returns the reservation at the end, so concurrent turns see each other and the final count equals actual usage (a turn that uses more than the reservation can overshoot a cap by at most the difference). **A turn runs to the end in a detached background task**, so a client that disconnects is still charged. Limits are checked after request validation, so a 422 takes no slot. `/confirm` is checked only when a confirmation is really pending, and only against daily quotas, without a window slot (refusing would strand the action); the front end re-enables the button when refused. **Redis unreachable → the advisor returns 503 (fail-closed)**, timeout 0.5 s; the advisor is the only paid route and nothing else touches Redis. `max_tokens`: 1,500 for answers, 200 for intent classification, in the body (`extra_body`). IP: `TRUST_FORWARDED_FOR` became `TRUSTED_PROXIES` (IPs, networks or host names, host names re-resolved every 30 s); production sets `caddy`; only when the peer is Caddy is the right-most `X-Forwarded-For` used, and the Caddyfile writes `header_up X-Forwarded-For {remote_host}` explicitly. Over the limit: 429 with `{"detail": {"code", "message", "retryAfter"}}` and `Retry-After`; the advisor page shows a Chinese message. The privacy policy draft mentions the limit records and retention. Review found 4 problems, fixed with tests: usage not charged when the client disconnected near the end (now a background task); concurrent turns passing before counters update (now reservations); malformed requests taking slots (now checked after validation); after the caddy container got a new IP, up to 30 s in which everyone counted as one IP (now re-resolved at most once a second on a mismatch). A second review round failed on an API limit; Claude's self-review found one more: the background task started only when the response began streaming, so a client disconnecting before that left the reservation forever (could exhaust the site quota); it now starts right after admission. Known, not handled: after a disconnect the turn keeps running, and a new message in the same conversation would write the same in-memory session concurrently (the front end disables sending during an answer and a reload starts a new conversation, so hard to trigger). Not done or not verified: anonymous users switching cookies are limited only by IP and site (by design); a full turn's real token count was not measured, so the defaults are estimates, **for the owner to review**.
- PR #44 (post-merge review fix, deployed 10-30, backup `~/db-backup-20261030-pre-withdraw.sql.gz`): when the admission script ran in Redis but its reply timed out (0.5 s), the 503 left the 8,000-token reservation and the window slot until the end of the day. The model gives every sentence with verbatim quotes in one function call; each sentence needs at least one quote of 12+ characters found verbatim in a chunk, and every number in the sentence must be in its quotes, otherwise the sentence is removed; if all are removed the answer is a refusal listing the pages read. The answer is sent whole after checking (no token streaming) and is labelled with the fetch date and "unverified" (待核验). Vectors: `snapshot_chunk_embeddings` + `python -m app.agent.embeddings --chunks` + beat (programs first, then chunks, at most 2,000 of each per run); **nothing happens without a key** (dry run: 134,843 chunks, about 4,200 requests, about 550 MB stored). The evaluation's gold answers were found with regular expressions over chunks, not from retrieval results; retrieval was looked at once before the real run (to check school recognition) and nothing was changed because of it; the two "gold sentence retrieved/cited" metrics were added after seeing the answers (a stricter measure; the recorded answers were not changed). Not done or not verified: the check covers only verbatim quotes and numbers, **not whether a quote supports the sentence or belongs to another program** (left to "summary faithfulness"); only the last message is considered (a follow-up like 那学费呢？ does not go to snapshots); in a mixed question (IELTS and tuition) the IELTS part is answered only if retrieved; non-English pages rely on a few listed foreign words; vector and hybrid ranking untested at the time (waiting for the SiliconFlow key; retrieval measured later in the PR #85 section below).

### Advisor dock: step events and the run interface (PR #96)

The second step of the line-map interface: the advisor sits in a dock beside the workspace and shows a turn as it happens. No OpenSpec change, by the same instruction as PRs #94 and #95. No new write tool was added; the two existing ones (the profile update and the portfolio change) are unchanged in what they can write.

- Scope: the stream (`api/app/routers/advisor.py`), the wording of steps (`api/app/agent/steps.py`), stopping (`api/app/agent/halt.py`, the graph's edges), the confirm question (`api/app/agent/tools.py`), citations (`api/app/agent/evidence.py`, `api/app/agent/answer.py`); the dock and the page (`web/components/advisor/`, `web/app/advisor.css`), the transcript (`web/lib/advisor-run.ts`), the reply's text (`web/lib/advisor-text.ts`), the shell (`web/components/shell/Shell.tsx`).
- Events: the stream keeps `intent`, `citations`, `tool`, `token`, `confirm`, `error` and `done` in their old order and adds `step` and `stopped`. A `step` opens with `status: "running"`, an `id`, a `kind` (`intent`, `retrieval`, `tool`), a `name`, a `title` and `args`; it closes under the same id with `done`, `empty`, `failed`, `waiting`, `declined` or `stopped`, `ms` and a one-line `result`. A confirmed change is written in a step of its own, `<call id>:write`. `error` events now carry a `code` in every case (`not_configured`, `busy`, `nothing_pending` and `confirm_in_progress` are new).
- What an event carries: a tool's reply is never copied into one. `api/tests/test_advisor_steps.py` writes a school name and a language score into a profile, has the model read the profile, the applications and the portfolio, and asserts that neither value appears anywhere in the step events (the profile step says how many fields are filled, "已填 2 项"). A tool the module does not know is reduced to its name, arguments cut at 80 characters and a generic outcome.
- Stop: `POST /api/advisor/stop` makes the graph end at its next edge. In the test, the stop arrives while the model call that asks for a profile update is in flight: the call finishes, the update never runs, its step closes as `stopped`, the stream ends with `stopped` and `done`, and the next message on the same thread runs normally. A second message on a thread whose turn is still running asks that turn to stop and waits for it (up to 20 s, then a `busy` error); a message whose client has gone by the time the thread is free does not start.
- Confirm: the question lists the target program and each stored value beside the value it becomes; the answer carries that list back, and the tool refuses to write when the portfolio no longer matches it (tested by editing the portfolio between the question and the answer). A change that would change nothing is refused without a question. A call that asks for a confirm runs in a step of its own: beside it, a profile update used to be saved while the turn waited and run again on the answer (the test counts one write).
- Citations: a requirement answer's citation carries the collected values (marks, language, academic requirement, deadlines, prerequisites; only the ones collected) and, for a deadline, the verified sentence it was read from. A page answer's citation carries the quotes that passed the check, cut from the stored page text by position rather than copied from the model, because the check folds case, spacing, quotes and dashes.
- Layout: three panes from 1440px (rail 236, dock 392). From 901 to 1439px the dock is 380px and folds the rail to 64px while it is open; at 1024px the workspace is then 580px wide, so the pages' 760px layouts were moved from a viewport media query to a container query on the workspace. At 900px and below there is no dock and /advisor is the 顾问 tab's screen.
