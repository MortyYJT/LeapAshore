- Notes: design in `openspec/changes/archive/2026-10-30-advisor-limits/`. Redis client `redis` (redis-py asyncio); local compose maps it to 127.0.0.1:56379, production does not expose it; `noeviction`, 256 MB. The subject is what `get_subject` returns (the account in sign-in mode, the anonymous cookie's id otherwise); **both subject and IP are checked** and either one full refuses. Sliding windows use sorted sets; one Lua script checks the three daily quotas and every window and records only when all pass (refused requests take no slot); time comes from Redis `TIME`. Defaults: subject 10/minute and 60/hour, IP 30/minute and 200/hour; daily tokens 200,000 per subject, 600,000 per IP, 2,000,000 for the site; "a day" is Beijing time. Daily quotas: the admission script reserves 8,000 tokens (`ADVISOR_TURN_TOKEN_RESERVE`) on the subject, IP and site counters; every model call adds its reported usage (LangChain callback); the turn returns the reservation at the end, so concurrent turns see each other and the final count equals actual usage (a turn that uses more than the reservation can overshoot a cap by at most the difference). **A turn runs to the end in a detached background task**, so a client that disconnects is still charged. Limits are checked after request validation, so a 422 takes no slot. `/confirm` is checked only when a confirmation is really pending, and only against daily quotas, without a window slot (refusing would strand the action); the front end re-enables the button when refused. **Redis unreachable → the advisor returns 503 (fail-closed)**, timeout 0.5 s; the advisor is the only paid route and nothing else touches Redis. `max_tokens`: 1,500 for answers, 200 for intent classification, in the body (`extra_body`). IP: `TRUST_FORWARDED_FOR` became `TRUSTED_PROXIES` (IPs, networks or host names, host names re-resolved every 30 s); production sets `caddy`; only when the peer is Caddy is the right-most `X-Forwarded-For` used, and the Caddyfile writes `header_up X-Forwarded-For {remote_host}` explicitly. Over the limit: 429 with `{"detail": {"code", "message", "retryAfter"}}` and `Retry-After`; the advisor page shows a Chinese message. The privacy policy draft mentions the limit records and retention. Review found 4 problems, fixed with tests: usage not charged when the client disconnected near the end (now a background task); concurrent turns passing before counters update (now reservations); malformed requests taking slots (now checked after validation); after the caddy container got a new IP, up to 30 s in which everyone counted as one IP (now re-resolved at most once a second on a mismatch). A second review round failed on an API limit; Claude's self-review found one more: the background task started only when the response began streaming, so a client disconnecting before that left the reservation forever (could exhaust the site quota); it now starts right after admission. Known, not handled: after a disconnect the turn keeps running, and a new message in the same conversation would write the same in-memory session concurrently (the front end disables sending during an answer and a reload starts a new conversation, so hard to trigger). Not done or not verified: anonymous users switching cookies are limited only by IP and site (by design); a full turn's real token count was not measured, so the defaults are estimates, **for the owner to review**.
- PR #44 (post-merge review fix, deployed 10-30, backup `~/db-backup-20261030-pre-withdraw.sql.gz`): when the admission script ran in Redis but its reply timed out (0.5 s), the 503 left the 8,000-token reservation and the window slot until the end of the day. The answer is sent whole after checking (no token streaming) and is labelled with the fetch date and "unverified" (待核验). Vectors: `snapshot_chunk_embeddings` + `python -m app.agent.embeddings --chunks` + beat (programs first, then chunks, at most 2,000 of each per run); **nothing happens without a key** (dry run: 134,843 chunks, about 4,200 requests, about 550 MB stored). The evaluation's gold answers were found with regular expressions over chunks, not from retrieval results; retrieval was looked at once before the real run (to check school recognition) and nothing was changed because of it; the two "gold sentence retrieved/cited" metrics were added after seeing the answers (a stricter measure; the recorded answers were not changed). Not done or not verified: the check covers only verbatim quotes and numbers, **not whether a quote supports the sentence or belongs to another program** (left to "summary faithfulness"); only the last message is considered (a follow-up like 那学费呢？ does not go to snapshots); in a mixed question (IELTS and tuition) the IELTS part is answered only if retrieved; non-English pages rely on a few listed foreign words; vector and hybrid ranking untested (waiting for the SiliconFlow key).
