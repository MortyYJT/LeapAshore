## 2026-10-30 账号与登录：邮箱验证码 + 服务端会话，登录模式用开关（Claude 自主（待 MortyYJT 复核））

## 2026-10-30 顾问限流与额度：Redis 滑动窗口 + 每日 token 上限，Redis 不可用时拒绝（Claude 自主（待 MortyYJT 复核））

- **决定**：设计全文在 `openspec/changes/archive/2026-10-30-advisor-limits/design.md`。要点：
  - Redis（`redis:7-alpine`）进本机和生产 compose，客户端 `redis`（redis-py 的 asyncio 客户端）；P1 的 Celery 复用它，所以 `noeviction` + 256 MB，满了宁可拒写也不悄悄丢计数或任务。生产不对外暴露端口、不设密码。
  - 身份：主体（登录模式下是账号，匿名模式下是匿名 cookie 的 id）和 IP 都查，任何一个超限就拒。匿名用户清 cookie 就是新主体，所以真正兜底的是 IP 限制和全站上限。
  - 滑动窗口（有序集合）+ 每日 token 计数，一个 Lua 脚本一次查完、全过才记一笔，被拒的请求不占名额。默认：主体 10 次/分钟、60 次/小时；IP 30 次/分钟、200 次/小时；每天 token 每主体 20 万、每 IP 60 万、全站 200 万（TASKS.md 定的）；一天按北京时间。全部是环境变量。
  - 日额度：放行时预扣 8,000 token（环境变量），按模型回报的用量累加，一轮结束归还预扣；一轮在后台任务里跑完，客户端断开也照样记账。没选「只事后记账」：新上下文审查指出客户端在最后一块（带用量）到达前断开就能让用量不入账，同时进来的多轮也会一起越过上限。`/confirm` 有待确认操作时才查，只查日额度不占窗口。
  - **Redis 连不上时顾问返回 503（fail-closed）**。没选 fail-open：顾问是唯一花钱的接口，fail-open 等于 Redis 一挂额度就失效；网站其他部分不依赖 Redis，影响只限顾问。
  - `max_tokens`：回答 1,500、意图分类 200，放请求体里——实测 DeepSeek 忽略 LangChain 默认发送的 `max_completion_tokens`。
  - IP：只有连接对端在 `TRUSTED_PROXIES`（生产是 `caddy`）里才读 `X-Forwarded-For` 最右一项；Caddyfile 显式把它设成 `{remote_host}`。替换原来的 `TRUST_FORWARDED_FOR`。
- **理由**：TASKS.md P0 第五条；MortyYJT 2026-10-30 授权 AI 自主决定。
- **待 MortyYJT 复核**：各项默认数字（没量过一轮完整对话的 token 数）；fail-closed 是否可接受。

## 2026-10-30 采集队列：Celery 只负责跑，状态在表里；队列不写目录库（Claude 自主（待 MortyYJT 复核））

- **决定**（设计见 `openspec/changes/archive/2026-10-30-collect-queue/`）：
  - 每个页面一个 Celery 任务；队列状态和每页最近一次结果放在新表 `collect_pages`，哪处要求变了记进 `requirement_changes`（Alembic `6afe86aaf7b6`，只加表）。broker 丢消息不丢进度：`python -m app.collect.queue resume` 重发。

  - 403/429、robots.txt 拒绝、已记录的拒绝：记下、不重试。超时、连接错误、5xx、模型传输错误：指数退避（60 秒起翻倍，封顶 1 小时，抖动），最多 4 次后记 `failed`。

  - 去重：HTML 的 sha256 或可见文本（规范化后）的 sha256 和上次一样，就不调模型、不记变更。可见文本不变而 HTML 变（CSRF、时间戳）很常见，只看 HTML 会白花钱。
  - 什么算「变了」：数字（雅思托福分数、建议与否、985/211 均分）和截止日期按值比；学术要求、先修课、只有文字的要求，只在**旧引文不再出现在新页面上**时才算变。模型每次截的引文片段不同，按引文比会把同一句话当成变化（本机冒烟实测出现过）。页面上一个值都没剩（多半是挑战页或渲染失败）就进 `needs_human`，不记一串「删除」。

  - **生产快照放 docker 命名卷 `snapshots`**（挂在 worker 的 `/app/var/snapshots`）；数据库只存学校 key 和 sha256，不存路径。生产镜像没有 Chrome，需要渲染的页面在生产记 `deferred`，回本机采。

  - 发现：`_schools.json` 给每所学校官方列表页（子代理只用 WebSearch 找 URL，没碰学校网站），列表页用快照工具抓，同站链接编号给模型挑哪些是授课型硕士项目页——模型只能回编号，不能编地址；项目名用链接文字，链接文字不像学位名（如「Learn more」）时用页面自己的第一个 `<h1>`。每校最多 60 个。可见文本不足 1,500 字的页面用 Chrome 渲染一次，以后都渲染。

## 2026-10-30 顾问对话存进 PG：Alembic 建表、确认按线程加锁、90 天不用就删（Claude 自主（待 MortyYJT 复核））

- **决定**（设计全文 `openspec/changes/archive/2026-10-30-advisor-persistence/design.md`）：
  - 用 `langgraph-checkpoint-postgres==3.2.0` 的同步 `PostgresSaver` + 自己的小连接池（最多 2 个），异步方法丢到线程里跑。没用 `AsyncPostgresSaver`：它绑死创建时的事件循环，uvicorn、测试客户端（每个请求一个循环）、Celery worker 是三个不同的循环。
  - **表由 Alembic 建**（`c4e8a1d2f6b9`，抄库里 0–9 号迁移的 SQL，并在 `checkpoint_migrations` 记成已执行），不在启动时调 `setup()`。理由：CI 和生产容器本来就跑 `alembic upgrade head`，表结构只有一个主人；`setup()` 建的表 Alembic 看不见，autogenerate 还会提议删掉它们（`env.py` 已排除这四张表）。库版本钉死，测试比对库的迁移条数和摘要，升级库时如果多了迁移会测试失败，要求另写一个只加不删的 revision。
  - 「只写一次」：确认请求先拿该线程的 PG advisory lock（单独连接，整轮持有，进程死了锁随连接释放），拿到后重读一次暂停状态；`confirm` 事件带中断 `id`，前端确认时带回，名字对不上就不执行；每一步存档用 `durability="sync"`；模型一次回复里提多个组合改动时只留第一个（LangGraph 同一步的中断共用一个 id，多个并行的确认会串答案）。写入本身是幂等的（工具按当前组合重算整份目标再整体替换）。
  - 每轮结束把线程剪到只剩最新一个存档（库自带 `keep_latest`，暂停中的改动不受影响），否则消息列表每一步存一份，线程按平方增长。
  - 对话跟着主体走：注销/90 天匿名清理在同一事务里删对话；首次登录合并时把匿名对话搬到账号下（同一个对话 id 账号已有的，丢匿名那份）；**90 天没动的对话在两种模式下都删**（匿名模式下主体清理不跑，不删的话表只会长；页面不保存对话列表，90 天没动的对话本来就打不开）。

## 2026-10-30 概括忠实度校验：模型判断引文能否推出概括，推不出就降级、不删（Claude 自主（待 MortyYJT 复核））

- **决定**：
  - **判什么**：每个过了 `verify` 的字段，把它说的话写成一句英文声明（学术要求、先修课的 `text`；雅思托福写成「Minimum / Recommended (not a minimum) … overall 6.5, no section below 6.0」，所以 `recommended` 和哪个数是总分、哪个是单项都在判；截止日期写成「Application deadline (label): 日期」；中国学生要求连同 985/211 和其他院校的分数），问模型「只看这条引文，能不能推出这句话」。学校、项目名只给上下文，不算证据。没写 `text` 的先修课就是引文本身，直接记 ok，不调模型。
  - **用哪个模型**：顾问的 `CHAT_*`（生产和本机都是 DeepSeek `deepseek-chat`，返回名 `deepseek-flash`），温度 0，function calling，一个项目一次请求（所有字段一起），坏答案重问一次。**本机这次回填也用 DeepSeek**（MortyYJT 说本机采集/抽取用 Claude 子代理，但这条的校验器本身就是要上生产的 DeepSeek 判官，回填和评估量的就是它；标注用的是 Claude 子代理）。
  - **降级 = 不删不改**：判决存在条目上（`summary_check` = ok / `unsupported: …` / `not checked: …`，`summary_sha` = 所判内容的摘要）。不是 ok 的值留在文件里、写明原因，导入器不写进库，项目 `待人工`（库里 `data_status` `待核验`）。没判过的（子代理采的、旧的）照旧可用。改了概括或引文，摘要对不上，判决作废（`verify --write` 会删掉）。模型没给判决或答案读不出来记 `not checked`，**和不忠实一样拦**（没查过的不放行），下次回填会重试。不动 `verified_at`。
  - **导入器**：只要有过了引文核对的值就照样处理这个项目，所以以前导入过、现在被降级的值会从库里清掉（变成未知），而不是因为「没有可用值」被跳过、留着旧值。

- **理由**：TASKS.md P1 第六条；红线「顾问不能说没有来源的判断」；MortyYJT 2026-10-30 授权 AI 自主决定。

## 2026-10-30 模型不可用时的降级（Claude 自主（待 MortyYJT 复核））

- **背景**：DeepSeek 账户余额用完（−0.06 元），生产和本机每次调模型都返回 HTTP 402「Insufficient Balance」（`insufficient_balance_error`，10-30 实测）。
- **决定**：`app/agent/llm.py` 的 `outage(error)` 把供应商的回答分两类：`account`（401、402、403，或 `insufficient_quota`：要人去充值/换 key，几分钟内不会好）和 `transient`（408、409、429、5xx、连不上、超时）；400 和答案读不出来不算不可用（是调用本身的问题）。
  - 顾问：任何一步（意图分类、ReAct、快照 RAG 的回答和判官）遇到不可用，整轮结束，SSE 发 `{"type":"error","code":"model_unavailable","message":"顾问暂时不可用，请稍后再试。"}`；本轮已有工具真的写入（确认执行的选校改动、更新的资料；只读工具、取消或被拒的改动不算）时后面加「这一轮里已经执行的操作已保存。」。其他异常是 `code: advisor_failed`、原来的「顾问暂时出错了」。HTTP 仍是 200 的流（错误发生在流里），预扣照常归还。
  - 意图分类遇到不可用不再回退到「通用问答」（回退只会再调一次同一个供应商），直接抛；读不出来的回答仍回退。
  - 判官（快照 RAG 第二次调用）遇到不可用不再当成「没判」而拒答——那样用户看到的是「找到了页面但不作判断」，像是库里没依据，而且 P2 的知识缺口会把它记成缺口。
  - 采集队列：抽取或判官遇到 `account` 类，页面记 `deferred`、`last_error` 以 `model unavailable: ` 开头，`fetched_at` 恢复成上次的值（和预算用完同样处理：照旧到期，第二天的 beat 会再挑到），上次的结果、快照哈希不动，不写 `requirement_changes`；已经付费的抽取照记账。同时在 Redis 里设一个 1 小时的标记（`collect:model-outage`），所有 worker 在这期间到了要调模型那一步就直接 `deferred`（抓取和「没变化」的判断照做）。`transient` 类照旧重试 4 次。
  - 忠实度回填（`faithful.backfill`）：遇到 `account` 类立即整体停止（报 `stopped_at_model_unavailable`），不再每个项目试 3 次；每个项目在副本上判，失败不留半截判决；一个项目都没判成的文件不重写。
- **理由**：MortyYJT 的要求（10-30）：用户看到清楚的中文提示、不 500、不丢状态、不半截写入、采集页面以后重试。MortyYJT 2026-10-30 授权 AI 自主决定。
- **没做**：顾问没加「供应商挂了就不调」的断路器（402 不收费、立即返回，没必要）；发现（`discover`）没改（手动命令，失败时什么都不写）。
- **待 MortyYJT 复核**：429 算「暂时」而不是「账户」：DeepSeek 的 429 是限速；如果换成用 429 表示额度用完的供应商，要看它的 `code`（已认 `insufficient_quota`）。

## 2026-10-30 知识缺口审核队列（P2 第一条）（Claude 自主（待 MortyYJT 复核））

- **决定**：设计见 `openspec/changes/archive/2026-10-30-knowledge-gaps/`。两张表：`knowledge_gaps`（一个缺口一行：路线、原因、学校、方向、学科词、页面主题、累计次数、审核状态；不含个人信息，长期保留）和 `knowledge_gap_reports`（每次拒答一行：提问原文前 500 字 + 提问人摘要 + 时间）。同一缺口按门槛自己的信号合并（路线|原因|学校|方向|学科词|主题 的 sha256；没认出学校时再加上折叠后的问题原文），不用模型、不做模糊匹配，审核人能看懂为什么合并。
- **记录哪些**：两个门槛的拒答、快照 RAG 答了但一句都核对不上（模型回答读不出来或判官没给判决时不记，那是模型的问题）、多校问题里被略过的学校（`school_missing`）。模型不可用（PR #65）整轮结束，不会记成缺口。记录失败只记日志，不影响回答。
- **提问人只存哈希**：`HMAC-SHA256(KNOWLEDGE_GAP_HASH_KEY, "knowledge-gap-reporter\n" + 主体 id)`；主体 id 是匿名 cookie 标识或登录模式下账号的主体 id，不用账号 id、邮箱、IP。密钥只在服务器 `deploy/.env`（部署时 Claude 在服务器上随机生成，没进仓库）；没配密钥时**不存提问记录**（存了也没法在注销时找到并删除；审查 #67 指出），只给缺口计数加一。每个主体一个哈希（不是每个缺口一个），这样删除只要一条查询；代价是同一人的几条提问能归到一起（提问原文本来也能）。
