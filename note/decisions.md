# 决策记录

只追加，不改旧条目。每条：日期、决定、理由、影响。属于某个 OpenSpec change 的决定优先写进那个 change，这里只记跨 change 的决定。

## 2026-10-10 先装开发流程 v2，再重新规划产品

- **决定**：顺序为 ① 装流程 v2（`claude/workflow-v2` 分支，从 main 开）→ ② 对整个产品做 brainstorm，用 SDD 重新规划和排期 → 再开发。M4（`stage-2-m4-conversations-and-proposals`）暂停，等 brainstorm 结论出来再决定保留、修改还是废弃。
- **理由**（MortyYJT 原话）：「我们这个产品其实是没有规划好要做什么的，我们现在来做，用 sdd，然后排期啥的开发」。
- **影响**：M4 分支 `dsh/stage-2-m4-conversations` 原样保留，不开 PR。M1–M3 学习材料按交接默认异步派给 dsh，不阻塞。

## 2026-10-10 分工：Codex 实现，dsh 出题

- **决定**：从现在起，实现由 Codex 负责（按 issue、在独立 worktree 里 TDD），dsh 负责出题和阶段复盘，不再做主要实现者。
- **理由**：MortyYJT 选了推荐项，没有另写理由。推荐时给的理由：dsh 对仓库历史最熟，适合写复盘；实现和出题分开，避免「自己考自己」。
- **影响**：分支前缀以后主要是 `codex/` 和 `claude/`；dsh 的产出放在 `note/interview/`。

## 2026-10-10 只装 guard hook，不装 verify hook

- **决定**：安装 `.claude/hooks/guard.sh`（PreToolUse），不装 `verify.sh`（Stop）。推翻了之前「两个 hook 都不装」的做法。
- **理由**：MortyYJT 选了推荐项，没有另写理由。推荐时给的理由：v2 由 Claude 自动推送、开 PR，需要真的拦住远端危险操作；`make verify` 要起数据库、跑截图，挂在每个回合结束时跑太慢。
- **影响**：完成前的检查仍靠手动跑 `make verify` 和 CI。

## 2026-10-10 重新规划的成功标准：对标指南者铺广度

- **决定**：以「对标指南者铺广度」为目标，不以「面试前演示一条完整闭环」为目标。
- **理由**：MortyYJT 选择，没有另写理由。Claude 提示过风险：核验工作量会暴涨，每项都做不深；离 11 月中旬到岗只剩 4–5 周。
- **影响**：范围按功能面和国家两个方向扩张，进度由核验吞吐量决定。

## 2026-10-10 广度先做院校库 + 规则分档

- **决定**：先把「官方数据采集 → 核验 → 入库」做成可复用的流水线，用澳八跑通，再按官方要求分冲刺 / 匹配 / 保底三档（不给概率）。加国家等于往流水线里加数据源。案例库不做（没有真实数据）。
- **理由**：MortyYJT 选了推荐项。推荐理由：院校库是其余功能的地基；现在澳八还是占位数据，先加国家只会多一份占位。
- **影响**：M4（会话）的优先级下降，去留在规格里定。

## 2026-10-10 核验分三档：待核验 / 机器核对 / 人工已核验

- **决定**：新增「机器核对」一档。agent 抓取官方页面并存快照，抓到的值必须能在快照原文里逐字找到才算机器核对。`verified_at` 仍然只由人来写。界面和分档结论如实标明依据属于哪一档。
- **理由**：MortyYJT 选了推荐项。推荐理由：只认人工核验，库的规模就被你每周能核的条数卡死，铺不开。
- **影响**：动到红线「Never mark unverified data as verified」的口径。机器核对 ≠ 已核验，`AGENTS.md` 的红线要在规格里同步改写措辞。

## 2026-10-10 数据进库：CRICOS 骨架 + 官方页采集（A+C）

- **决定**：项目骨架（名称、层级、学制、总学费、学科）从 CRICOS 开放数据导入。录取要求从学校官方项目页采集：存快照 → 模型抽取（带引文）→ 引文逐字核对 → 人工队列兜底。
- **理由**：MortyYJT 选了推荐项，没有另写理由。推荐理由：CRICOS 一次性铺满澳八的项目，不用逐页抓取；模型抽取受引文约束，是第一次真正接入模型。
- **已核实**：data.gov.au 的 `CRICOS Courses.csv` 更新于 2026-09-30，含 `Course Level`、`Duration (Weeks)`、`Tuition Fee`（**整个课程的总学费，不是年费**）、学科分类、`Expired`。

## 2026-10-10 分档沿用「冲刺 / 匹配 / 保底」

- **决定**：分档名称沿用冲刺 / 匹配 / 保底，与指南者一致。
- **理由**：MortyYJT 选择，没有另写理由。Claude 提示过：没有录取数据，这三个词容易被理解成概率，和红线有张力。
- **影响**：规格里必须写明，这三档**只表示对官方要求的满足程度**，每档的判定规则要公开；界面要声明「不是录取概率」，并列出每条依据的出处和核验档。

- **理由**：MortyYJT 选了推荐项。推荐理由：等院校库和分档做完、要接入对话顾问时，再按新范围重写。

## 2026-10-10 不批准 S1–S5 设计；改为先列功能点、做静态前端原型，再补后端

- **决定**：上面那份「S1–S5 + 事实模型 + 分档规则」草案**没有批准**。改为：先讨论功能点 → 在 `web/` 里做静态可点击原型（fixture 数据，示例数据明确标注；能用 CRICOS 真实数据的就用）→ 再按原型补后端。按纯界面轨道走：聊天里定设计 → 构建 → 真实浏览器验证 → 截图。
- **理由**（MortyYJT 原话）：「时间太长，然后我觉得先讨论出功能点都有啥，然后做一个静态前端网页，然后再去补后续」。
- **影响**：上面四条关于数据进库、核验三档、分档命名、抽取模型的决定继续有效，留给补后端时用；草案里的排期作废。

## 2026-10-10 产品定位：中介的获客与初筛工具

- **决定**：OfferPilot 的用途是帮 MortyYJT 的留学中介业务**初步筛选学生**：让学生对留学有初步概念，减少沟通成本，留下有价值的学生，再由 MortyYJT 作为中介人工帮他们申请。产品要提供多种转人工咨询的方式。
- **理由**（MortyYJT 原话）：「我做这个的目的是初步筛选学生，让学生对留学有初步概念，减少沟通成本，留下有价值的学生，然后我作为中介帮他申请这样子」。
