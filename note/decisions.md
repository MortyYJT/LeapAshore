## 2026-10-30 账号与登录：邮箱验证码 + 服务端会话，登录模式用开关（Claude 自主（待 MortyYJT 复核））

- **决定**：设计全文在 `openspec/changes/archive/2026-10-30-account-login/design.md`。要点：
  - 账号只拥有一个数据主体（`accounts.client_id` → `clients`），所有用户表仍按 `client_id`；登录后请求解析成账号的主体。没选「每张表加 account_id」：要改所有查询和迁移数据，换来的东西主体间接层都能表达。
  - 登录模式是开关 `AUTH_ENABLED`，代码默认关；`make api-dev-bg` 本机打开；生产 compose 设 `APP_ENV=production`，生产在登录模式下没有 SMTP 配置就拒绝启动，日志发信后端在生产拒绝发送。所以先部署代码是安全的，SES 配好再开。
  - 限流先放 PostgreSQL（Redis 在下一条才来）：发码用按邮箱的 advisory lock，校验用 `FOR UPDATE`，首次登录用 `INSERT … ON CONFLICT (email) DO NOTHING`。每邮箱每天 10 次、每 IP 每天 30 次（环境变量可调）；新码作废旧码，所以一个邮箱一次只能猜一个码，一天最多 50 次。

## 2026-10-30 顾问检索：校名按数据识别，学科按 Program.field，筛选进 SQL（Claude 自主（待 MortyYJT 复核））

- **决定**：设计全文在 `openspec/changes/archive/2026-10-30-advisor-retrieval/design.md`。要点：
  - 评估集 80 条（调参 50 / 报数 30），由 Claude 对照本机库标注；标签是「学校 id + 可选 `Program.field` + 可选项目名正则」，相关项目在评估时从库里查（还要求有录取要求数据和可引用来源）。标签和库对不上时评估直接拒绝打分。Recall@K 分母取 min(K, 相关数)，K 从代码 `evidence.TOP_K` 读（=4）。
  - 校名：库里的中文名（繁简都认，用 OpenCC 的字表折叠，4,105 个字，Apache-2.0，放 `api/data/advisor/zh_t2s.json`，不加依赖）、英文名、英文名括号里的缩写，加一份手工简称表 `api/data/advisor/university_aliases.json`（按 university id，131 所共 267 个简称）。重叠时取最长匹配（西悉尼大学不算悉尼大学）。代码里不出现任何校名。没选「建表存别名」：165 所学校，匹配本来就在 Python 里做，建表只多一次迁移和种子。

## 2026-10-30 顾问限流与额度：Redis 滑动窗口 + 每日 token 上限，Redis 不可用时拒绝（Claude 自主（待 MortyYJT 复核））

## 2026-10-30 采集队列：Celery 只负责跑，状态在表里；队列不写目录库（Claude 自主（待 MortyYJT 复核））

- **决定**（设计见 `openspec/changes/archive/2026-10-30-collect-queue/`）：
  - 每个页面一个 Celery 任务；队列状态和每页最近一次结果放在新表 `collect_pages`，哪处要求变了记进 `requirement_changes`（Alembic `6afe86aaf7b6`，只加表）。broker 丢消息不丢进度：`python -m app.collect.queue resume` 重发。
  - 限速：Redis 里按主机的令牌桶（容量 1、每 2 秒一个，和快照工具原来的间隔一样），所有 worker 共用，`www.x` 和 `x` 算同一个；要等 10 秒以上就把任务以 countdown 放回队列，不占 worker。命令行快照工具仍用原来的文件锁。
  - 403/429、robots.txt 拒绝、已记录的拒绝：记下、不重试。超时、连接错误、5xx、模型传输错误：指数退避（60 秒起翻倍，封顶 1 小时，抖动），最多 4 次后记 `failed`。
  - **拒绝记录 30 天后过期**（新记录带时间，过期后用同一个身份再问一次）；这次之前记的没有时间，仍然永久有效，要人手删。理由：生产按月重采，一次偶发 403 不该让一个站永远不采；但旧记录不知道是哪天记的，不能编时间。
  - 去重：HTML 的 sha256 或可见文本（规范化后）的 sha256 和上次一样，就不调模型、不记变更。可见文本不变而 HTML 变（CSRF、时间戳）很常见，只看 HTML 会白花钱。
  - 什么算「变了」：数字（雅思托福分数、建议与否、985/211 均分）和截止日期按值比；学术要求、先修课、只有文字的要求，只在**旧引文不再出现在新页面上**时才算变。模型每次截的引文片段不同，按引文比会把同一句话当成变化（本机冒烟实测出现过）。页面上一个值都没剩（多半是挑战页或渲染失败）就进 `needs_human`，不记一串「删除」。

  - **生产快照放 docker 命名卷 `snapshots`**（挂在 worker 的 `/app/var/snapshots`）；数据库只存学校 key 和 sha256，不存路径。生产镜像没有 Chrome，需要渲染的页面在生产记 `deferred`，回本机采。
  - 预算：按模型返回的 token 数和 DeepSeek 高峰价（输入未命中 2 元/百万、命中 0.04、输出 8，10-30 读价格页）算上限费用，每次调模型前查；补采用 `backfill` 键 100 元，生产 beat 每天 `COLLECT_DAILY_BUDGET_CNY`（默认 1 元），每天最多重采 200 页、30 天没采过的才采。
  - 发现：`_schools.json` 给每所学校官方列表页（子代理只用 WebSearch 找 URL，没碰学校网站），列表页用快照工具抓，同站链接编号给模型挑哪些是授课型硕士项目页——模型只能回编号，不能编地址；项目名用链接文字，链接文字不像学位名（如「Learn more」）时用页面自己的第一个 `<h1>`。每校最多 60 个。可见文本不足 1,500 字的页面用 Chrome 渲染一次，以后都渲染。
  - beat：每天 04:07（北京）重采到期页面；03:17 跑 90 天匿名数据清理——**只在 `AUTH_ENABLED` 开时**才删，匿名模式下所有用户都是匿名的，这条规则是给登录模式写的（handoff「切到登录模式」第 6 步因此不用再加 cron）。
  - worker 用 `--pool threads`：macOS 上 Python 3.12 的 prefork 是 spawn 模式，Celery 任务一跑就报 `not enough values to unpack`（本机实测）；任务都是等网络，线程池够用，生产也用同一种，免得两边行为不同。
- **理由**：TASKS.md P1 第二条；MortyYJT 2026-10-30 授权 AI 自主决定。
- **待 MortyYJT 复核**：拒绝 30 天过期是否可以接受；生产 beat 每天 1 元、200 页的默认额度；变更只记不自动入库（要人工 export 再导入）是否太慢；匿名模式下不跑 90 天清理。

## 2026-10-30 顾问对话存进 PG：Alembic 建表、确认按线程加锁、90 天不用就删（Claude 自主（待 MortyYJT 复核））

- **决定**（设计全文 `openspec/changes/archive/2026-10-30-advisor-persistence/design.md`）：
  - 用 `langgraph-checkpoint-postgres==3.2.0` 的同步 `PostgresSaver` + 自己的小连接池（最多 2 个），异步方法丢到线程里跑。没用 `AsyncPostgresSaver`：它绑死创建时的事件循环，uvicorn、测试客户端（每个请求一个循环）、Celery worker 是三个不同的循环。
  - **表由 Alembic 建**（`c4e8a1d2f6b9`，抄库里 0–9 号迁移的 SQL，并在 `checkpoint_migrations` 记成已执行），不在启动时调 `setup()`。理由：CI 和生产容器本来就跑 `alembic upgrade head`，表结构只有一个主人；`setup()` 建的表 Alembic 看不见，autogenerate 还会提议删掉它们（`env.py` 已排除这四张表）。库版本钉死，测试比对库的迁移条数和摘要，升级库时如果多了迁移会测试失败，要求另写一个只加不删的 revision。
  - 「只写一次」：确认请求先拿该线程的 PG advisory lock（单独连接，整轮持有，进程死了锁随连接释放），拿到后重读一次暂停状态；`confirm` 事件带中断 `id`，前端确认时带回，名字对不上就不执行；每一步存档用 `durability="sync"`；模型一次回复里提多个组合改动时只留第一个（LangGraph 同一步的中断共用一个 id，多个并行的确认会串答案）。写入本身是幂等的（工具按当前组合重算整份目标再整体替换）。
  - 每轮结束把线程剪到只剩最新一个存档（库自带 `keep_latest`，暂停中的改动不受影响），否则消息列表每一步存一份，线程按平方增长。
  - 对话跟着主体走：注销/90 天匿名清理在同一事务里删对话；首次登录合并时把匿名对话搬到账号下（同一个对话 id 账号已有的，丢匿名那份）；**90 天没动的对话在两种模式下都删**（匿名模式下主体清理不跑，不删的话表只会长；页面不保存对话列表，90 天没动的对话本来就打不开）。
  - 用户没点确认就发了新消息时，给模型看的历史里补一条「未执行」的工具回复（存的线程不改）。实测 DeepSeek 对没回复的工具调用返回 400，对话会一直坏下去。
  - 隐私政策改成「对话存在数据库，90 天不用删除、注销时删除」。
- **理由**：TASKS.md P1 第三条；MortyYJT 2026-10-30 授权 AI 自主决定。
- **待 MortyYJT 复核**：所有账号的对话 90 天不用就删（不只是匿名）；匿名对话在登录时搬进账号；隐私政策里这两句措辞。

## 2026-10-30 混合检索：dump/restore 换 pgvector 镜像、只换排序不换门槛、国家只区分同名学校（Claude 自主（待 MortyYJT 复核））

## 2026-10-30 概括忠实度校验：模型判断引文能否推出概括，推不出就降级、不删（Claude 自主（待 MortyYJT 复核））

- **决定**：
  - **判什么**：每个过了 `verify` 的字段，把它说的话写成一句英文声明（学术要求、先修课的 `text`；雅思托福写成「Minimum / Recommended (not a minimum) … overall 6.5, no section below 6.0」，所以 `recommended` 和哪个数是总分、哪个是单项都在判；截止日期写成「Application deadline (label): 日期」；中国学生要求连同 985/211 和其他院校的分数），问模型「只看这条引文，能不能推出这句话」。学校、项目名只给上下文，不算证据。没写 `text` 的先修课就是引文本身，直接记 ok，不调模型。
  - **用哪个模型**：顾问的 `CHAT_*`（生产和本机都是 DeepSeek `deepseek-chat`，返回名 `deepseek-flash`），温度 0，function calling，一个项目一次请求（所有字段一起），坏答案重问一次。**本机这次回填也用 DeepSeek**（MortyYJT 说本机采集/抽取用 Claude 子代理，但这条的校验器本身就是要上生产的 DeepSeek 判官，回填和评估量的就是它；标注用的是 Claude 子代理）。
  - **降级 = 不删不改**：判决存在条目上（`summary_check` = ok / `unsupported: …` / `not checked: …`，`summary_sha` = 所判内容的摘要）。不是 ok 的值留在文件里、写明原因，导入器不写进库，项目 `待人工`（库里 `data_status` `待核验`）。没判过的（子代理采的、旧的）照旧可用。改了概括或引文，摘要对不上，判决作废（`verify --write` 会删掉）。模型没给判决或答案读不出来记 `not checked`，**和不忠实一样拦**（没查过的不放行），下次回填会重试。不动 `verified_at`。
  - **导入器**：只要有过了引文核对的值就照样处理这个项目，所以以前导入过、现在被降级的值会从库里清掉（变成未知），而不是因为「没有可用值」被跳过、留着旧值。

  - **评估**：从全部 29,393 个可判字段里按种子 20261030 抽 100 个（回填写判决之前抽），加上快照 RAG 那次真实运行留下的 75 句，由新上下文的 Claude 子代理在看不到判官结果的情况下标「supported / unsupported」；判官只真实跑一次，CI 回放录下的答案。提示词只在 UT Austin 18 个项目和抽取测试的虚构页面上调过（改了两处：先修课/学术要求不加前缀；985/211 不加 Double First-Class 注释——这两处都是我写的声明模板自己加了引文没有的词，判官照规则拦了）。

## 2026-10-30 模型不可用时的降级（Claude 自主（待 MortyYJT 复核））

- **背景**：DeepSeek 账户余额用完（−0.06 元），生产和本机每次调模型都返回 HTTP 402「Insufficient Balance」（`insufficient_balance_error`，10-30 实测）。
- **决定**：`app/agent/llm.py` 的 `outage(error)` 把供应商的回答分两类：`account`（401、402、403，或 `insufficient_quota`：要人去充值/换 key，几分钟内不会好）和 `transient`（408、409、429、5xx、连不上、超时）；400 和答案读不出来不算不可用（是调用本身的问题）。
  - 顾问：任何一步（意图分类、ReAct、快照 RAG 的回答和判官）遇到不可用，整轮结束，SSE 发 `{"type":"error","code":"model_unavailable","message":"顾问暂时不可用，请稍后再试。"}`；本轮已有工具真的写入（确认执行的选校改动、更新的资料；只读工具、取消或被拒的改动不算）时后面加「这一轮里已经执行的操作已保存。」。其他异常是 `code: advisor_failed`、原来的「顾问暂时出错了」。HTTP 仍是 200 的流（错误发生在流里），预扣照常归还。
  - 意图分类遇到不可用不再回退到「通用问答」（回退只会再调一次同一个供应商），直接抛；读不出来的回答仍回退。
  - 判官（快照 RAG 第二次调用）遇到不可用不再当成「没判」而拒答——那样用户看到的是「找到了页面但不作判断」，像是库里没依据，而且 P2 的知识缺口会把它记成缺口。
  - 采集队列：抽取或判官遇到 `account` 类，页面记 `deferred`、`last_error` 以 `model unavailable: ` 开头，`fetched_at` 恢复成上次的值（和预算用完同样处理：照旧到期，第二天的 beat 会再挑到），上次的结果、快照哈希不动，不写 `requirement_changes`；已经付费的抽取照记账。同时在 Redis 里设一个 1 小时的标记（`collect:model-outage`），所有 worker 在这期间到了要调模型那一步就直接 `deferred`（抓取和「没变化」的判断照做）。`transient` 类照旧重试 4 次。
  - 忠实度回填（`faithful.backfill`）：遇到 `account` 类立即整体停止（报 `stopped_at_model_unavailable`），不再每个项目试 3 次；每个项目在副本上判，失败不留半截判决；一个项目都没判成的文件不重写。

## 2026-11-20 顾问管理申请的工具（Claude 自主（待 MortyYJT 复核））

- **背景**：`docs/product/PRD-multi-device.md` 3.6。MortyYJT 11-20 交代：顾问能读申请、能提议修改，确认后才写入；不许编造日期；写入只发生一次；另做一套工具选择的评估集，但不许实跑（本机没有模型 key，花钱没批准）。流程同 PR #94 到 #97：先代码和测试，文档最后补，不写 OpenSpec。数字见 `docs/measurements.md`「Advisor tools for managing applications」。
- **工具怎么分**：一种修改一个工具，共四个，加上原有的组合工具。
  - `propose_manual_application`（学校、项目名）、`propose_application_deadline`（申请 id，加学校库日期的 id，或申请者说的日期和轮次）、`propose_application_status`（申请 id、状态）、`propose_material_tick`（申请 id、勾或不勾、加一行备注）。
  - 理由：每种修改的参数少，规则也不同；只能带状态的调用带不了日期（有测试逐个检查工具的参数名）。一个通用工具会把「给了日期就必须给来历」这类条件规则交给模型自己遵守。
  - 学校库里有的项目仍然用 `propose_portfolio_change` 的 add 加入（它带档位），新工具只管学校库没有的项目，所以「加申请」不会有两个工具都能做。改状态同理：组合工具的说明里去掉了 set_status，代码还收，是为了发布前停在确认卡片上的对话还能继续。
  - 材料现在只有一个勾（全部材料是否就绪）。工具、卡片和说明都按「勾」来叫，内部用 `ALL_MATERIALS` 这一个键，以后做逐项勾选时加键。申请者只说某一样材料备好时，说明里要求模型不要勾，可以提议记进备注。
- **日期怎么证明不是编的**：
  - 学校库的日期：模型只传 `program_deadlines` 那一行的 id，日期、轮次名和来源链接由服务器读。那一行必须属于这条申请的项目，否则拒绝。模型同时传了自己的日期也拒绝。
  - 申请者说的日期：服务器自己读这段对话里申请者的消息（`app/agent/stated.py`），找到这一天才出卡片。顾问或工具写过的日期不算。只认写全的日期和「几月几日」；没写年份的按那条消息发出当天之后的下一个这一天算（消息现在带发送日期），消息里别处出现了年份（「1月15日（2028年）」「去年12月1日」）就不读；「1/15」「下周五」「月底」和链接里的日期都不读。
  - 轮次、材料备注、手动添加的学校和项目名同样只能是申请者写过的原话（整词匹配，「around 12」不算说过「Round 1」）。备注和名称是自由文本，不这样管的话，编出来的要求或日期可以写在里面。
  - 写入后一律是「待核对」。顾问没有任何参数能写 `checked_at`，核对只能由申请者在「我的申请」里做。
  - 申请者说的日期替换学校库日期时，学校库的来源链接不保留（那个页面是学校库日期的来源）；申请者自己填过的来源保留。
  - 这套规则证明的是日期出自申请者的话，证明不了它是不是这条申请的截止日期：申请者在对话里写的任何日期（问句里的、说别的项目的、生日）都算「说过」。把它记成哪条申请的什么，由确认卡片交给申请者看。
- **学校库日期的显示**：记录里存的日期如果和学校库里这个项目的某一条日期、来源都相同，读出来就标「学校库采集」，否则标「自己填的」。没有加列，也没有迁移。申请者在表单里手填了同样的日期和来源，也会标成采集（内容确实相同）；学校库以后重新采集改了日期，这条记录会变回「自己填的」。
- **写入规则**：
  - 写入走 `app/services/application_records.py`，是从 HTTP 路由里抽出来的同一份代码，路由只负责把结果翻成 404、409、422。
  - 卡片是按哪个版本列的，就带哪个版本去写。版本和当时的各项值存在暂停的对话里，确认时由服务器读回，不发给浏览器。记录在这期间被改过就不写，回复里列出别处改了什么（轮次、日期、状态、材料、核对状态；备注只说改过）。
  - 只写一次：更新靠版本，同一个版本只能被写一次；手动添加带一个由对话和调用 id 算出来的键，同一次调用再跑一遍会找到上一次建的记录。重复点击和重启靠原有的对话锁和检查点。
  - 进程在写入之后、检查点之前被杀掉时，卡片还在等确认。再确认一次不会重复写；回复和那一步都说「已经是这样」，不说「没有执行」，因为改动其实已经写进去了。
  - 手动添加在加锁之后再查一次重名，两个对话同时确认同一个项目只会加一条。HTTP 接口没有这条规则，表单仍然可以加重名的。
  - 组合工具现在也带 base：这一次运行读到哪些行，写的时候就声明哪些行，中间被别的设备改过就拒绝（PR #94 留下的那一项）。
- **状态的叫法**统一成总览那一套：考虑中、准备中、已提交、收到录取、未录取、已放弃。组合页、确认卡片、工具说明和工具回复都改了，前端只留一份（`web/lib/taxonomy.ts`），后端一份（`app/agent/confirm.py`）。
- **评估集**（`api/evals/tool_choice_cases.json`，`api/evals/run_tools.py`）：
  - 97 题，Claude 写的，没有人工复核。每题标期望调用的工具和关键参数。评估账号在运行时现建、跑完删除；学校库项目用真实的四个，手动添加的两个是为评估编的。
  - 一轮跑到结束或第一张确认卡片为止，不回答卡片，所以不会写入任何提议。先提议一项、确认后才做另一项的做法因此看不到，有一题会因此算错（题里写明了）。

## 2026-11-20 自己的模型密钥（Claude 自主（待 MortyYJT 复核））

- **背景**：`docs/product/PRD-multi-device.md` 3.5。顾问默认用站长的密钥和原有的限流、每日额度；申请者可以填自己的密钥。测到的数字见 `docs/measurements.md`「Own model key」。
- **密钥怎么走**：只存在浏览器的 localStorage（`leapashore:model-key`），每次 `/api/advisor/chat`、`/confirm`、`/key/check` 请求放在 `Authorization: Bearer` 头里，另一个头 `X-Model-Provider` 写服务商的 id。服务器读成一个 `ApplicantKey` 对象，放进一个上下文变量，这一轮结束就没有了（`api/app/agent/model_key.py`）。
  - 没有放进 LangGraph 的 state 或 config：这两样都会随 checkpoint 存库。等待确认后继续的那一轮，密钥从新的请求里取。
  - `ApplicantKey` 打印出来是占位符，pickle、copy、JSON 序列化都会报错。
  - 用 `Authorization` 而不是自定义头：Caddy 转发失败时（比如 api 重启的几秒里返回 502）会把请求头写进错误日志，默认只遮 `Authorization` 这几个。第一版用的 `X-Model-Key` 会被原样写进去，是审查发现、本机用 Caddy 2.11.4 实测确认后改的。
- **哪里会漏，怎么堵的**：
  - 第一次跑测试就抓到一条：LangGraph 会把失败步骤的异常存进 `checkpoint_writes`，服务商的 401 报错里带着密钥时，密钥就进了数据库。现在用自己密钥的那一轮，异常只存类名和 HTTP 状态码，存库的每个值再按字节抹一遍（`app/agent/checkpoint.py` 的 `_ScrubbingSerde`）。
  - 日志：这一轮里产生的每条日志记录都过一遍，带密钥的换成 `[key removed]`，异常只留调用栈的文件行号和类名，不留报错原文（服务商可能回显密钥的后几位）。`_stream` 里自己密钥的分支只记错误种类。
  - 判官出错时留在 trace 里的那句话（`answer.py`）同样只留类名。
  - 抹除只看这一轮自己的上下文，不用进程级的名单：密钥是调用方随便发的一个字符串，如果按全局名单抹，有人把「密钥」写成 `tool_calls`，别人对话的存档就被改坏了（审查发现）。密钥至少 20 位，只允许字母、数字和 `._~+/=-`，这些字符在 JSON、repr 和网址里都不会被转义，出现时一定是原样。
- **限流**：带自己密钥的请求不查、不预留、不计站长的每日 token 额度，频率窗口照旧（同一组窗口，和默认请求共用）。带自己密钥的确认请求两样都不查，所以不需要 Redis。
- **服务商**：服务器上一张固定的表，页面只发 id，发不了地址。
  - DeepSeek：`https://api.deepseek.com`，模型 `deepseek-flash`，请求体加 `thinking: {type: disabled}`。官方文档写明不传时默认开启思考，而思考模式下指定函数的 `tool_choice` 会返回 400，意图分类和判官都用指定函数。

## 2026-11-20 材料归并：数据、逐项勾选、提取工具（Claude 自主（待 MortyYJT 复核））

- **背景**：`docs/product/PRD-multi-device.md` 3.7。分两个 PR：这一条是数据、逐项勾选、顾问和提取工具；材料线路图另记。**还没有做过任何一次真实提取**，学校库里没有一条材料要求，所以没有精确率、召回率，也不写任何这类数字。测到的事实见 `docs/measurements.md`「Material merging」。
- **谁来提取**（MortyYJT 定的）：由 Claude Opus 5.5 子代理读已存的页面快照，不用 DeepSeek。仓库里只有工具（`python -m app.collect.material_extract`）和给子代理的说明（`api/data/requirements/README.md`「Brief for a material-extracting agent」），工具本身不调模型、不抓网页。
- **采集文件里放在哪**：每个项目在 `fields` 旁边多一个 `materials` 块，不放进 `fields`。
  - `fields` 是采集队列和 DeepSeek 抽取的地盘：队列重采一页会整块换掉 `fields`，放进去就被冲掉；队列的导出现在会把 `materials` 原样带过去。
  - 材料是另一趟读页面读出来的，对的是它自己记下的那个快照（`materials.snapshot_sha256`）。页面后来被重采，项目的快照号变了，材料块还指着它读的那一版。
  - 项目的 `status`（机器核对 / 待人工）只看 `fields`，材料条目通不过不影响它。
- **三种状态分开**：没有 `materials` 块是「还没提取」；有块、条目为空、`rejected` 为 0 是「读过，这一页没有列材料」；有块但交上来的条目全被拒，两样都不算，仍按没提取处理。库里用 `programs.materials_snapshot_sha256` 是否为空区分前两种，接口上是 `materials: null` 和 `materials: {items: []}`。界面和顾问都不把「没提取」说成「不需要」。
- **一条材料怎么算通过**（`api/app/collect/materials.py`，整条通过或整条拒绝，从不改值）：类型在固定的九种里；原文逐字在快照里；写了份数的，这个数必须在原文里（数字，或英文的 one 到 twenty）；说明（`note`）里出现的数字也必须在原文里；`other` 必须有说明，因为类型本身说不出是什么。
  - 「a CV」不算写了份数。页面只用别的语言写数量的，份数留空。这是偏严的一边：宁可没有份数，不要一个原文里找不到的数。
  - 数字要独立出现才算：`1,000` 里的 1、`2nd` 里的 2、`A4` 里的 4、数字日期里的日和月都不算。原文折叠掉空白和不可见字符后至少 10 个字符。
  - 这只是字面检查。「references are required」能在「No references are required」里找到；一个数是不是这个项目的、是不是份数，字面上也看不出来。这些只有标注集能量出来。
  - `note` 是提取者自己的概括，除了数字这一条没有别的检查。PRD 说忠实度判官要覆盖这些新字段，**这次没有做**：现有判官调用 DeepSeek，按要求不接付费调用。
- **入库**：新表 `program_materials`，每行一条材料，带原文和出处页面。`python -m app.collect.importer --materials-only <文件>` 只写学校库里已有项目的材料，不建项目，不动来源、快照版本、其他字段和截止日期；整份导入也会写材料。同样内容再导一遍不产生任何写入（测试按 SQL 语句断言）。
  - 写材料不清也不设页面的 `verified_at`：人工核验核的是当时页面上那几项值，材料是另一批机器核对的原文。
  - 文件里没有可用的材料块时不动库里已有的材料，否则队列重采后的一次整份导入会把材料清空。
  - 「有要求」的口径（`has_requirement_data`）没有改，材料不计入。改了会同时改动学校库筛选、每校计数和顾问的证据门。
- **勾选存什么**：`application_plans.material_ticks` 是「材料键 → 勾的时候这条要求的摘要」。键是类型名，同一类型的第二条起是 `类型-2`。读的时候摘要对得上才算勾着；官网要求变了（份数、说明或原文任一变化）摘要就对不上，这一项回到没勾，并标成「要求改过」。
  - 另一个做法是把键做成原文的哈希，要求一变勾就直接消失。没选它，因为那样申请者看不出是自己没勾还是要求变了。
- **原来的整体勾怎么迁移**：`materials_ready = true` 的行，迁移时在它自己的清单里加一条已勾的「全部材料（改版前的整体自查）」，不转成逐项的勾。原来那个勾是在工具一条材料都没列的时候打的，把它展开成对每项材料的勾，等于替申请者确认了他没见过的清单。旧列留着不再读写，回滚到旧镜像还能用；回滚只丢升级之后打的勾。迁移在本机用一行 true、一行 false 试过。
- **自己的清单**：每条申请都有（`custom_materials`，最多 40 行）。手动添加的申请和还没提取的项目只有这一份；提取过的项目两份并列，因为采集的清单可能不全。行的 id 必须是 `c-` 开头，和学校库的材料键不会重名。
- **`materialsReady` 还在接口里**，改成算出来的：清单里至少有一项且全部勾上。总览的终点实心、「接下来」的提示还用它。一项都没列的申请不算就绪。还没提取的学校库项目，自己列的几项全勾上时，总览写「自列材料已勾完」，卡片写「（自己列的，官网要求还没提取）」，不写「材料已就绪」。写入时不再接受 `materialsReady`，旧页面带着它保存会得到 422，刷新后正常（和 #94 一样）。
- **同步规则不变**：勾选和清单都走 `PATCH /api/application-records/{id}`，必须带 `baseVersion`，过期返回 409 和服务器上的记录。勾选按键增量发送（没提到的键不动），自己的清单整份替换。重复发同样的勾不动版本号。
- **顾问**：
  - `get_my_applications` 带每条申请的材料：名称、份数、说明、官网原文、出处、是否勾了、要求是否在勾之后变过，以及 `materialsExtracted`。
  - `propose_material_tick` 多一个参数 `material`，只能是这条申请清单里已有的一项（学校库材料的键，或自己清单里的 id），或 `all`（清单里的全部）。清单里没有的材料不能勾，顾问也不能往清单里加行，所以它没有地方写进一条自己编的材料要求。还没提取的项目返回「学校库还没有整理这个项目的材料清单」。
  - 卡片列出每一项的旧值和新值。卡片出来之后学校库的要求变了（重新导入），确认时不写入。
  - 证据行多一项「申请材料」：没提取写「未提取」，读过但没列写「官网这一页没有列出」。
  - 工具选择评估集从 97 题加到 103 题，材料类 12 题。学校库里没有材料，所以评估账号的清单都是自己列的条目（题集说明里写了是编的）。**这套题仍然没有实跑。**
- **审查之后加的四条规则**：
  - 网页上勾一项材料时，请求要带上页面当时显示的那条要求的摘要（`materialBasis`）。记录的版本号不会因为学校库重新导入而变，光靠版本号拦不住「页面开着的时候 2 封变成了 3 封，申请者照旧页面勾了」。摘要对不上按过期处理，返回 409 和现在的记录，什么都不写。
  - 提取可以撤回：`material_extract withdraw` 把材料块标成撤回，导入时把库里这个项目的材料清掉、退回「还没提取」。交上来的条目全被拒的块同样处理。没有块的文件仍然不动库里的材料。
  - 确认卡片和步骤里的材料名字要分得清：`other` 用它的说明当名字，同名的两条（两篇个人陈述）各带上说明或原文开头。
  - 证据行里的材料后面自带「机器核对原文，未经人工核验」。整行的「数据状态」说的是人核过的那几项，材料没有人核过。
- **评估**（`python -m evals.materials`）：标注集格式、空白模板、检查、打分、重放。单位是（项目，材料类型）；只给「提取用的快照和标注用的快照相同」的项目打分，没提取的和快照不同的单独计数、不进比率。份数一致率只在任一方写了份数的配对上算。标注者不能看提取结果：模板里没有提取内容，读页面的命令也不显示提取状态。仓库里只有手写的假页面夹具，没有标注集，也没有打分结果；有一条测试在真实结果进仓库之前会一直提醒这一点。
