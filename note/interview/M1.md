## 1. 这一阶段做了什么、为什么

- 问题：阶段一的档案只存在浏览器 `localStorage`，换设备或清存储就丢；项目目录也硬编码在
  前端。M1 建 FastAPI + PostgreSQL 骨架，把档案与项目数据落库，前端档案页改为读写服务端。
- 技术选型（`note/superpowers/specs/2026-10-06-stage-2-database-design.md` §3.1、§3.7）：
  单一 PostgreSQL，不引入第二个数据库——旧项目 PostgreSQL + MySQL 双库出过「删号没传播到
  第二个库」；迁移用 Alembic，ORM 用 SQLAlchemy 2.0，后端 FastAPI + Pydantic v2，PostgreSQL
  16 跑在 Docker 里。
- 身份：匿名 cookie `offerpilot_client` + `clients` 表，不做登录（`api/app/deps.py:get_client_id`、
  `api/app/models/client.py`）。被否决的替代是先做账号登录；数据模型留出「以后平滑加账号」的形状。
- `get_client_id` 只种 cookie、不碰数据库；建行放在 `load_or_create_profile`（`api/app/deps.py`），
  由 endpoint body 在 FastAPI 校验完请求体之后调用。被否决的替代是把插库放进依赖：422 请求会留下
  `clients` + `profiles` 孤儿对（开发库实测 221 对，184 个 `school_name` 为 null），而 422 不带
  `Set-Cookie`，这些行永远无法再被寻址。
- 首次访问的并发：`load_or_create_profile` 用 savepoint + `IntegrityError` 把输家当成「已存在」，
  而不是「先查后插」；也没有用 `ON CONFLICT` upsert，因为 `clients` 与 `profiles` 两张表都可能撞，
  savepoint 释放后 `session.get` 读回赢家提交的那一行就对（`api/app/deps.py`；
  `api/tests/test_first_contact_race.py`）。
- 来源治理统一成 `sources` + `source_versions` 两张表，`programs.source_id` NOT NULL
  （`api/app/models/source.py`、`api/app/models/program.py`）；被否决的替代是每个实体各存一份
  URL / 核验状态，那会重复实现两套来源版本机制（spec §3.2）。
- `sources.verified_at` 可空、没有 server default；代码与种子禁止硬编码核验日期
  （`scripts/check-no-fake-dates.cjs`）。
- 项目数据由 Python 种子从 `web/lib/programs.ts` 逐条转写，配快照 + 对账脚本
  （`scripts/seed-programs.snapshot.json`、`scripts/verify-programs-mirror.cjs`），防止前端改了
  种子没跟着改。
- 前端档案读写改走 `GET/PATCH /api/profile`（`web/lib/api.ts:fetchProfile/patchProfile`、
  `web/app/page.tsx`）。
- 验收偏差（记录在 `note/stage-1-MVP.md` 第 574–606 行）：计划写「Modify `web/lib/store.ts`、
  组件不变」，实际没改 `store.ts`，档案仍被写进 localStorage 并在下次加载反向合并；同时改了 5 个
  组件。评审发现后，最终修复轮让 `store.ts` 不再读写档案（`web/lib/store.ts`），并把
  `mergeServerProfile` 定为「服务端有值（含空串）即胜出，只有 null 才回退本地默认值」
  （`web/lib/api.ts:mergeServerProfile`）。
- 交付物：4 条 Alembic 迁移、7 张表（`clients`/`profiles`/`sources`/`source_versions`/`universities`/
  `programs`/`program_prerequisites`；`note/stage-1-MVP.md:583` 写「六张表」，漏了 `source_versions`）、
  `/api/health`、`/api/profile`、`/api/programs`；浏览器走查截图
  `docs/screenshots/22-profile-restored-from-server.png`。
- 本阶段不用 JSONB；`source_versions` 建了但还没有写入方；`profiles.avatar_document_id`（把头像挂到
  文档）、登录、上传与 agent 都留给后面（spec §7、计划第 1784 行「本批不覆盖」）。
- 核对入口：`api/app/routers/profile.py`、`api/app/routers/programs.py`、`api/app/seed.py`、
  `api/seed_cli.py`、`api/tests/test_profile_api.py`、`api/tests/test_programs_api.py`。
- 本阶段没有单独的 `docs/verification/` 证据文档（那时还没有 —— 待核验是否只是习惯后来才形成）。
  现有证据是 `note/stage-1-MVP.md`、计划末尾的自检表和走查截图。
