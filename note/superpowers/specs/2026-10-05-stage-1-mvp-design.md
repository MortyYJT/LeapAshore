# OfferPilot 第一阶段 MVP 设计

日期：2026-10-05
状态：**已实现骨架**（本设计在骨架落地后补写，用于固化已批准的决策；非"先设计后实现"）

## 1. 背景

原 OfferPilot 是 vibe coding 产物，功能齐全（60 个 API 路由）但从未跑通，且存在两处诚实性问题：
`verified_at` 是硬编码默认值 `"2026-07-14"`，8 所大学的 `threshold` 完全没有来源字段。

本次重构的约束条件：

- 面试时间 2026-10-12，另有 6 天需用于 hot100 与八股准备 → 留给本项目的实际时间约 1 天。
- 技术设计可参照另一个同类项目，但**业务必须不同**。
- 产品判断：面试官不会细看代码，但会问"这两个项目有什么区别"。

## 2. 产品形态

**可视化流程图是主界面，Agent 是背后维护它的东西。**

用户说「我雅思考了 6.5」→ 图上"语言准备"节点状态变化。
用户点开节点 → 看到还要准备什么、什么时候截止、来源是哪个官方页面。

这个形态解决了一个真问题：Agent 系统最难的是状态不可见、难调试。把申请状态画成图 = 把黑盒变白盒。

## 3. 用户流程

```
引导（Duolingo 风格，10 步，顶部绿色进度条 + x/y）
  → 「背景已获取，正在生成方案」
  → 申请组合选择（冲 / 稳 / 保）
  → 主界面：首页 | 流程进度 | 个人中心 | 留学顾问
```

引导步骤：学历 → 国内/海外 → **学校（自动识别档次，或自报层次）** → 专业 → 均分（任意满分制）
→ 目标学位 → 目标方向 → 语言成绩 → 预算 → 入学时间

## 4. 领域模型

六个对象，全部定义在 `web/lib/types.ts`：

| 对象 | 作用 |
|---|---|
| `Profile` | 申请档案（院校层次、均分、专业、语言、目标、预算） |
| `Program` | 招生项目 + `SourceCitation` + `dataStatus` |
| `PortfolioItem` | 申请组合（冲/稳/保 + `needsReview` 标记） |
| `Roadmap` / `RoadmapPhase` / `PhaseTask` | 6 阶段路线图 + 材料项 |
| `SourceCitation` | 来源引用（`verifiedAt` 可为 `null`） |

## 5. 关键设计决策

### 5.1 院校层次识别

- 985（39 所）/ 211（116 所，含 985）来自教育部公开名单，是稳定事实，可自动识别。
- 支持 40+ 常用简称（北大、北邮、华科、西电…）。
- 识别不到时**明确告诉用户"没有匹配到公开名单"并要求手动选层次**，不猜。
- 提供"不想填校名？直接选层次"出口。
- **QS 排名不做自动断言**（逐年变化），由用户自报区间。

### 5.2 确定性资格判定（`lib/eligibility.ts`）

- 只有 985 / 211 与"双非 + 项目录入了非 211 基线"两种情况才自动分档。
- 一本/二本/专科/海外 → 返回「需要人工核验」，**不套用统一基线**（各校通常有单独名单）。
- 语言要求含"单项"但用户未提供单项时 → 需要人工核验。
- 均分低于基线或要求相关背景而不满足 → 存在门槛缺口，不给出档位。

### 5.3 流程图不引入图引擎

拓扑固定（6 阶段线性 + 项目分支），用 CSS Grid 排节点 + 绝对定位画连线即可。
7 天窗口里少一个依赖就是少一个调试风险（React Flow 会带来 SSR、样式隔离、自定义节点三块工作）。

### 5.4 数据诚实性（硬约束，见 AGENTS.md §9）

- 6 个项目全部 `dataStatus: "待核验"`。
- `verifiedAt: null`（不是任何硬编码日期）。
- 所有时间 `scheduleOrigin: "suggested"`，界面标"系统建议 · 非官方日期"。
- 官方截止日期字段留空，界面显示"待核验"。

## 6. 非目标（本阶段明确不做）

Milvus 混合检索 · MCP · Langfuse · ONNX 分类器 · Docker/CI-CD · 真实学校数据核验 · 账号体系 · Agent

## 7. 验收标准

| 项 | 标准 |
|---|---|
| 构建 | `make build` 通过（含 TypeScript 类型检查） |
| 端到端 | `make screenshots` 走完引导 → 选校 → 主界面 → 刷新 |
| 运行期错误 | 浏览器 JS 错误为 0 |
| 持久化 | 刷新后仍在主流程 |
| UI 文案 | 不出现面向工程师的术语（意图分流、证据门禁、字段名） |
