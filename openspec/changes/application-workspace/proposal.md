## Why

Applicants need a personal workspace to manage multiple master's applications with different deadlines, materials and statuses. The current homepage emphasizes generic phase metrics and the catalogue-only portfolio cannot capture a project outside the school library.

## What Changes

- Add a per-applicant application workspace combining existing saved selections and manually added applications.
- Support application round, editable deadline, source URL, explicit human date confirmation, status and material readiness/notes.
- Replace overview metrics with actionable applications, current roadmap tasks, a first-application empty state and a contextual AI entry.
- Keep the catalogue, portfolio confirmation, roadmap and advisor operational.
- Refresh README screenshots, product description and PRD around personal application management; label planned features honestly.

## Capabilities

### New Capabilities
- `personal-application-workspace`: Personal application records, deadline management, actionable overview and onboarding.

### Modified Capabilities

None. Existing catalogue selection APIs retain their contract.

## Impact

An additive application-plan table and scoped API; frontend workspace and applications page; navigation and product documentation; migration, ownership, compatibility and browser checks. No new framework or external integration. Reminders and automatic submission remain out of scope.
